Kinglet collects logs from any app that can make an HTTP request, stores them
in a single SQLite or libSQL database, and gives you a live-tailing UI with
substring search — all on one small container.

<CardGrid>
  <Card title="Tiny by default">
    One process, one database, zero external services. ~150–250 MB of RAM —
    sized for a small VPS.
  </Card>
  <Card title="Log from anything">
    NDJSON or JSON over HTTP. curl, Vector, Fluent Bit, or the in-repo Node
    SDK — if it can POST, it can log to Kinglet.
  </Card>
  <Card title="Fast to search">
    SQLite FTS5 trigram indexing means substring matches (`"timeout"`) just
    work, plus a live tail over server-sent events.
  </Card>
  <Card title="Alerts that don't cry wolf">
    Watch for instant matches, error-rate spikes, or a cron that went silent —
    delivered to a webhook, Discord, or Slack with cooldowns and auto-resolve.
  </Card>
  <Card title="Yours to run">
    Docker Compose in, Litestream backups out. MIT licensed, no phone-home,
    no telemetry.
  </Card>
  <Card title="Storage you choose">
    SQLite by default, libSQL for local files or hosted Turso, ClickHouse on
    the roadmap — one small interface, swappable drivers.
  </Card>
</CardGrid>

## Where it's going

- **Node SDK extensions** — a pino transport and a zero-code console preload
  for the existing in-repo SDK.
- **PHP** — a Monolog handler for Laravel, Symfony, and WordPress.
- **More receivers** — OTLP for OpenTelemetry pipelines, and syslog so
  nginx/php-fpm ship with zero code changes.
- **ClickHouse driver** — the same storage interface, for when a single node
  stops being enough.
