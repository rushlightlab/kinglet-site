Kinglet is self-hosted. The fastest path is the public Docker image - no clone,
no build. If you already run Coolify or Dokploy, jump to their guides in
[Self-hosting](/self-hosting/#coolify).

<Aside type="caution" title="Exposing this beyond localhost?">
  Read [Security](/security/) first. It covers TLS, narrowing `KINGLET_TRUSTED_PROXIES`, strong
  secrets, API-key offboarding, webhooks, and image pinning. Do not use the all-private-ranges
  shortcut.
</Aside>

## Docker (one command)

```bash
docker run -d --name kinglet \
  --restart unless-stopped \
  -p 8080:3000 \
  -v kinglet-data:/data \
  -e KINGLET_BASE_URL=http://localhost:8080 \
  ghcr.io/rushlightlab/kinglet:latest
```

Open `http://localhost:8080`.

If you didn't set an admin password, the generated one is printed in the logs
and saved in `/data/admin-password.txt`:

```bash
docker exec kinglet cat /data/admin-password.txt
```

Sign in with `admin@kinglet.local` (or the email you set through
`KINGLET_ADMIN_EMAIL`) and that password.

<Aside type="tip" title="Pin a version">
  `:latest` is convenient for a trial. For production, pin a release tag such as `:0.3.0`, or a
  digest for an immutable deployment. See [Updates and image
  pinning](/security/#updates-and-image-pinning).
</Aside>

## Docker Compose (single host)

Use this when Docker runs directly on the server. Coolify and Dokploy have their
own compose definitions below — don't publish a host port there.

Create `docker-compose.yml`:

```yaml
services:
  kinglet:
    image: ghcr.io/rushlightlab/kinglet:0.3.0
    restart: unless-stopped
    ports:
      - "8080:3000"
    environment:
      KINGLET_BASE_URL: http://localhost:8080
      # KINGLET_ADMIN_EMAIL: you@example.com
      # KINGLET_ADMIN_PASSWORD: choose-a-strong-password
    volumes:
      - kinglet-data:/data

volumes:
  kinglet-data:
```

```bash
docker compose up -d
```

If you leave the admin password unset, read the generated one with:

```bash
docker compose exec kinglet cat /data/admin-password.txt
```

<Aside type="tip" title="Coolify or Dokploy?">
  The image is public, so neither platform needs registry credentials. Follow the
  [Coolify](/self-hosting/#coolify) or [Dokploy](/self-hosting/#dokploy) guide in Self-hosting. On
  those platforms, remove the `ports:` mapping and use `expose: ["3000"]` — the platform proxy
  handles routing, and `8080` may already be taken on the host.
</Aside>

## Create your first API key

1. Open **Settings → Projects**.
2. Choose **manage** next to the project.
3. Create a key with **ingest** (and **query** if scripts should read logs).
4. Copy it now — it is shown once.

```bash
curl -X POST http://localhost:8080/v1/events \
  -H "Authorization: Bearer kl_…" \
  -H "Content-Type: application/x-ndjson" \
  --data-binary '{"level":"info","message":"hello from my app","service":"my-app"}'
```

The event appears in the live tail immediately. If the project is empty, that
first event also seeds the histogram.

More clients — TypeScript, Python, Go, PHP, curl, Vector — are in
[HTTP ingestion](/ingestion/).

## From source

For development or a custom build, clone the repository and run both dev
servers (Node 26+ and pnpm 10+):

```bash
git clone https://github.com/rushlightlab/kinglet.git
cd kinglet
pnpm install
pnpm dev
```

The API listens on `:3000` and the UI on `:5173`.

<Aside type="note" title="Going to production">
  Set `KINGLET_BASE_URL` to your public HTTPS origin, use a persistent volume at `/data`, and pin a
  release tag or digest. The full checklist, TLS setup, backups, and platform guides are in
  [Self-hosting](/self-hosting/); the hardening checklist is in [Security](/security/).
</Aside>
