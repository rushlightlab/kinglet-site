Kinglet is self-hosted today: this page covers running your own instance —
deployment, configuration, sizing, backups, and TLS.

## Deploy

Kinglet ships as a multi-arch image (`linux/amd64` + `linux/arm64`) at
`ghcr.io/rushlightlab/kinglet` — the repository's release workflow publishes it.

```yaml
# docker-compose.yml
services:
  kinglet:
    image: ghcr.io/rushlightlab/kinglet:latest   # pin a release tag when available (e.g. :0.3.0)
    ports:
      - "8080:3000"
    environment:
      KINGLET_DB_PATH: /data/kinglet.db
      KINGLET_RETENTION_DAYS: 14
    volumes:
      - kinglet-data:/data
    restart: unless-stopped

volumes:
  kinglet-data:
```

```bash
docker compose up -d       # pulls the right architecture automatically
```

<Aside type="tip" title="Building from source">
  Prefer your own build? The repository README covers `pnpm install && pnpm dev`
  for development and `docker build -t kinglet .` for a local image.
</Aside>

<Aside type="note" title="Pinning versions">
  Create and push a release tag (e.g. `git tag v0.3.0 && git push origin v0.3.0`),
  then pin `:0.3.0` in production — `:latest` moves on every push to `main`.
  Available tags are listed on the repository's packages page.
</Aside>

<Aside type="caution" title="GHCR access">
  GHCR packages start private even when the repository is public. For anonymous
  `docker pull`, make the package public once (Packages → kinglet → Package
  settings → Change visibility → Public). Otherwise run `docker login ghcr.io`
  first.
</Aside>

## Configuration

| Env var | Default | What it does |
| --- | --- | --- |
| `KINGLET_PORT` | `3000` | HTTP port inside the container |
| `KINGLET_STORAGE` | `auto` | `sqlite`, `libsql`, or `auto` (picks by db path scheme) |
| `KINGLET_DB_PATH` | `data/kinglet.db` (image: `/data/kinglet.db`) | Plain path → SQLite; `libsql://`/`https://`/`file:` → libSQL |
| `KINGLET_DB_AUTH_TOKEN` | — | Auth token for remote libSQL/Turso |
| `KINGLET_ADMIN_EMAIL` | `admin@kinglet.local` | Bootstrap administrator email (when no administrator exists) |
| `KINGLET_ADMIN_PASSWORD` | *(generated)* | Bootstrap administrator password (when no administrator exists) |
| `BETTER_AUTH_SECRET` | *(generated, persisted)* | Session signing secret — set explicitly for multi-instance installs |
| `KINGLET_TRUSTED_PROXIES` | — | CIDRs allowed to set `X-Forwarded-For` |
| `KINGLET_ALLOW_PRIVATE_WEBHOOKS` | — | Allow private/internal webhook targets (SSRF escape hatch) |
| `KINGLET_DISABLE_LEGACY_TOKENS` | — | Disable workspace-wide `tok_…` superuser tokens |
| `KINGLET_SESSION_DAYS` | `30` | Web session lifetime |
| `KINGLET_BASE_URL` | — | Public HTTPS origin — secure cookies and alert deep links |
| `KINGLET_TOKENS` | *(auto-generate)* | Legacy global tokens — all projects, full access |
| `KINGLET_RETENTION_DAYS` | `14` | Delete events older than this |
| `KINGLET_MAX_EVENTS_PER_PROJECT` | `1000000` | Hard cap on retained events per project (`0` = unlimited) |
| `KINGLET_MAX_DB_MB` | `4096` | Hard cap on local database size in MB (`0` = unlimited) |

## Sizing

- **RAM**: ~150–250 MB steady state.
- **CPU**: 2 vCPUs are enough for a busy small app; throughput depends on event
  size and query volume. Ingest is batched SQLite writes, not per-request round
  trips.
- **Disk**: roughly a few hundred MB per million retained events, depending on
  payload size. With the default 14-day retention, a small app stays in
  single-digit gigabytes.

## Backups

The store is one SQLite database (`kinglet.db` plus `-wal`/`-shm` while running).
[Litestream](https://litestream.io/) replicates it continuously to S3-compatible
storage with a one-line sidecar:

```yaml
litestream:
  image: litestream/litestream
  volumes:
    - kinglet-data:/data
  command: replicate /data/kinglet.db s3://your-bucket/kinglet
```

## TLS and upgrades

- A ready-made Caddy setup lives in `deploy/` (`Caddyfile` +
  `docker-compose.tls.yml`). It obtains certificates automatically, sets HSTS,
  and keeps Kinglet off the public network — only Caddy publishes 80/443.
- Put Caddy or nginx in front for automatic TLS; the container speaks plain
  HTTP on its port. Set `KINGLET_BASE_URL` to the public HTTPS origin so
  session cookies are `Secure` and alert links are correct.
- Upgrades: `docker compose pull && docker compose up -d`. Graceful shutdown
  flushes SQLite on `SIGTERM`, so `docker compose stop` is safe.
