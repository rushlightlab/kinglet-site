Kinglet is self-hosted today: this page covers running your own instance.
The Docker image is public, so no registry login is needed. Pick the path that
matches your setup:

| Path | Best for |
| --- | --- |
| [Docker one command](#docker-one-command) | a quick trial on a single server |
| [Docker Compose](#docker-compose) | a single server with explicit configuration |
| [Coolify](#coolify) | an existing Coolify installation |
| [Dokploy](#dokploy) | an existing Dokploy installation |
| [From source](#from-source) | development or a custom build |

## Before you deploy

Set these for anything beyond localhost:

| Variable | Why |
| --- | --- |
| `KINGLET_BASE_URL` | Public origin, e.g. `https://logs.example.com`. Required for secure cookies, origin checks, and alert links. It must match the browser URL. |
| `BETTER_AUTH_SECRET` | 32+ random bytes. Optional for one instance (a secret is generated and persisted in `/data/auth-secret.txt`), required when several instances share a database. |
| `KINGLET_ADMIN_EMAIL` / `KINGLET_ADMIN_PASSWORD` | Used only when no administrator exists. After that they are ignored. |
| `KINGLET_TRUSTED_PROXIES` | Set to your proxy networks when running behind Caddy, Traefik, Coolify, or Dokploy. Otherwise all clients share the proxy's rate-limit bucket. |
| `KINGLET_DB_PATH` | `/data/kinglet.db` in the image. Keep the volume mounted at `/data`. |

Generate a secret with:

```bash
openssl rand -base64 32
```

No OpenSSL (Windows, slim images)? Node works too:

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
```

If you leave it unset, Kinglet generates one on first boot and stores it at
`/data/auth-secret.txt`. Set a new value later only if you accept that every
existing session is signed out.

For a platform proxy, the private Docker ranges are a safe starting point:

```dotenv
KINGLET_TRUSTED_PROXIES=172.16.0.0/12,10.0.0.0/8,192.168.0.0/16
```

## Docker one command

```bash
docker run -d --name kinglet \
  --restart unless-stopped \
  -p 8080:3000 \
  -v kinglet-data:/data \
  -e KINGLET_BASE_URL=http://localhost:8080 \
  ghcr.io/rushlightlab/kinglet:0.3.0
```

Open `http://localhost:8080`. If you did not set an admin password, read the
generated one from the logs or the volume:

```bash
docker logs kinglet
# or
docker exec kinglet cat /data/admin-password.txt
```

For a public server, set `KINGLET_BASE_URL=https://logs.example.com` before the
first boot.

<Aside type="tip" title="Pin versions">
  `:latest` moves with each release. Pin a version tag such as `:0.3.0` in
  production, or use a digest for an immutable deployment.
</Aside>

## Docker Compose (single host)

Use this when Docker runs directly on the server. On Coolify or Dokploy, use
the platform sections below instead.

```yaml
services:
  kinglet:
    image: ghcr.io/rushlightlab/kinglet:0.3.0
    restart: unless-stopped
    ports:
      - "8080:3000"        # standalone only — remove behind Coolify/Dokploy
    environment:
      KINGLET_DB_PATH: /data/kinglet.db
      KINGLET_BASE_URL: https://logs.example.com
      KINGLET_ADMIN_EMAIL: you@example.com
      KINGLET_ADMIN_PASSWORD: change-me-please
      BETTER_AUTH_SECRET: ${BETTER_AUTH_SECRET:?set BETTER_AUTH_SECRET}
      KINGLET_TRUSTED_PROXIES: 172.16.0.0/12,10.0.0.0/8,192.168.0.0/16
    volumes:
      - kinglet-data:/data

volumes:
  kinglet-data:
```

<Aside type="caution" title="Coolify and Dokploy: no host port">
  The `ports:` mapping is only for Compose running directly on a server. On
  Coolify or Dokploy, remove it and use `expose: ["3000"]` instead — the
  platform proxy reaches the container over the compose network. Publishing
  `8080` is a common `address already in use` failure because the host usually
  has something on it already.
</Aside>

Put `BETTER_AUTH_SECRET=...` in a `.env` file, then:

```bash
docker compose up -d
```

If you leave the admin password unset, read the generated one with
`docker compose exec kinglet cat /data/admin-password.txt`.

For TLS without a platform, use the Caddy sample in `deploy/`:

- `deploy/docker-compose.tls.yml`
- `deploy/Caddyfile`

It terminates TLS, sets HSTS, and keeps Kinglet off the public network.

## Coolify

Coolify's **Docker Image** resource deploys the public image without a Git
repository or build.

### 1. Create the Docker Image app

Create or open a project, then choose **+ New → Docker Image**.

### 2. Choose the image

Set the image name to `ghcr.io/rushlightlab/kinglet` and the tag to `0.3.0`
(or `latest`). No registry credentials are needed.

### 3. Set the port

Open **General** and set **Ports Exposes** to `3000`.

### 4. Add environment variables

Add these under **Environment Variables** (runtime):

```dotenv
KINGLET_BASE_URL=https://logs.example.com
KINGLET_ADMIN_EMAIL=you@example.com
KINGLET_ADMIN_PASSWORD=change-me-please
BETTER_AUTH_SECRET=<32+ random bytes>
KINGLET_TRUSTED_PROXIES=172.16.0.0/12,10.0.0.0/8,192.168.0.0/16
```

### 5. Add persistent storage

Open **Persistent Storage → Add → Volume Mount** and set the destination to
`/data`.

### 6. Add the domain

Open **Domains**, add `https://logs.example.com`, and target port `3000`.

### 7. Deploy

Click **Deploy**, wait for it to finish, then open the domain.

The app writes its database and generated auth secret under `/data`, so the
volume mount is required. If you didn't set an admin password, the generated one
appears in the application's runtime logs on first boot. Redeploy after changing
the image tag or runtime environment.

See Coolify's [Docker Image guide](https://coolify.io/docs/applications/deployments/docker-image)
and [Persistent Storage guide](https://coolify.io/docs/applications/configuration/persistent-storage)
for the current UI details.

## Dokploy

Dokploy deploys prebuilt images through a **Docker Compose** service. Its
Application build types are Git/Dockerfile-based, so Compose is the right fit
for the published image.

### 1. Create a Docker Compose service

Create or open a project, then create a **Docker Compose** service.

### 2. Paste the compose file

```yaml
services:
  kinglet:
    image: ghcr.io/rushlightlab/kinglet:0.3.0
    restart: unless-stopped
    expose:
      - "3000"
    env_file:
      - .env
    volumes:
      - kinglet-data:/data
    security_opt:
      - no-new-privileges:true
    cap_drop:
      - ALL

volumes:
  kinglet-data:
```

Don't add a `ports:` mapping here. Dokploy routes the domain through Traefik to
the compose network; `expose` is enough, and a host port can collide with
Dokploy itself or another app.

### 3. Add environment variables

Use the **Environment** tab. Dokploy writes these to `.env`; the
`env_file: .env` line loads them into the container.

```dotenv
KINGLET_BASE_URL=https://logs.example.com
KINGLET_ADMIN_EMAIL=you@example.com
KINGLET_ADMIN_PASSWORD=change-me-please
BETTER_AUTH_SECRET=<32+ random bytes>
KINGLET_TRUSTED_PROXIES=172.16.0.0/12,10.0.0.0/8,192.168.0.0/16
```

<Aside type="caution" title="Replace every placeholder">
  Change `logs.example.com` to your actual host in both `KINGLET_BASE_URL` and
  the domain below. `KINGLET_BASE_URL` must match the origin in the browser
  exactly. If it still points at `logs.example.com`, the page loads but sign-in
  fails with `403 INVALID_ORIGIN`.
</Aside>

### 4. Add the domain

Open **Domains → Add Domain**: host `logs.example.com`, container port `3000`,
HTTPS with Let's Encrypt enabled.

### 5. Deploy

Click **Deploy**. Dokploy adds the Traefik networking; redeploy after domain or
compose changes.

The named volume keeps the SQLite database and auth secret across deployments;
Dokploy's volume backups can target named volumes. If you didn't set an admin
password, the generated one appears in the service logs on first boot.

### Pull fails with `denied: denied`

The image is public, so this is almost always a stale registry login on the
Dokploy server. Docker sends the saved `ghcr.io` token and GHCR rejects it
instead of falling back to anonymous access. Remove the login on the host:

```bash
docker logout ghcr.io
docker pull ghcr.io/rushlightlab/kinglet:latest
```

Then redeploy the compose service. If the host uses a credential helper, delete
the `ghcr.io` entry from `~/.docker/config.json` instead. If you *want* private
authenticated pulls, create a classic GitHub token with `read:packages`, then add
or update the GHCR registry under Dokploy's **Registry** settings with that
token as the password.

### `address already in use` on port 8080

The compose file publishes a host port. Dokploy doesn't need one: remove
`ports:` and keep `expose: ["3000"]`, then add the domain in **Domains** with
container port `3000`. If you only need temporary host access, map a free port
such as `18080:3000` instead of `8080`.

See Dokploy's [Docker Compose guide](https://docs.dokploy.com/docs/core/docker-compose)
and [Domains guide](https://docs.dokploy.com/docs/core/domains) for the current
UI details.

## Configuration

| Env var | Default | What it does |
| --- | --- | --- |
| `KINGLET_PORT` | `3000` | HTTP port inside the container |
| `KINGLET_STORAGE` | `auto` | `sqlite`, `libsql`, or `auto` (picks by db path scheme) |
| `KINGLET_DB_PATH` | `/data/kinglet.db` | Local SQLite path; `libsql://`/`https://`/`file:` → libSQL |
| `KINGLET_DB_AUTH_TOKEN` | — | Auth token for remote libSQL/Turso |
| `KINGLET_BASE_URL` | — | Public HTTPS origin — secure cookies and alert deep links |
| `BETTER_AUTH_SECRET` | *(generated in `/data`)* | Session signing secret; set explicitly for multi-instance installs |
| `KINGLET_TRUSTED_PROXIES` | — | CIDRs allowed to set `X-Forwarded-For` |
| `KINGLET_ADMIN_EMAIL` | `admin@kinglet.local` | Bootstrap administrator email (when no administrator exists) |
| `KINGLET_ADMIN_PASSWORD` | *(generated)* | Bootstrap administrator password (when no administrator exists) |
| `KINGLET_SESSION_DAYS` | `30` | Web session lifetime |
| `KINGLET_RETENTION_DAYS` | `14` | Delete events older than this |
| `KINGLET_MAX_EVENTS_PER_PROJECT` | `1000000` | Hard cap on retained events per project (`0` = unlimited) |
| `KINGLET_MAX_DB_MB` | `4096` | Hard cap on local database size in MB (`0` = unlimited) |
| `KINGLET_ALLOW_PRIVATE_WEBHOOKS` | — | Allow private/internal webhook targets (SSRF escape hatch) |

## Sizing

- **RAM**: ~150–250 MB steady state.
- **CPU**: 2 vCPUs are enough for a busy small app; throughput depends on event
  size and query volume. Ingest is batched SQLite writes, not per-request round
  trips.
- **Disk**: roughly a few hundred MB per million retained events, depending on
  payload size. With the default 14-day retention, a small app stays in
  single-digit gigabytes.

## Backups

The store is one SQLite database (`kinglet.db` plus `-wal`/`-shm` while running).
[Litestream](https://litestream.io/) replicates it continuously to S3-compatible
storage with a one-line sidecar:

```yaml
litestream:
  image: litestream/litestream
  volumes:
    - kinglet-data:/data
  command: replicate /data/kinglet.db s3://your-bucket/kinglet
```

On Coolify or Dokploy, use the platform's volume backup for the `/data` volume.
Don't copy only the `.db` file from a live WAL store.

## Upgrades

- **Docker**: pull the new tag, remove the old container, and start it again with
  the same `/data` volume.
- **Compose**: `docker compose pull && docker compose up -d`.
- **Coolify**: change the image tag under General, then **Deploy**.
- **Dokploy**: change the image tag in the compose service, then **Deploy**.

Pin a release tag in production; `:latest` moves with each release. Migrations
run automatically on boot.

## Troubleshooting

### The page loads but sign-in returns `403 INVALID_ORIGIN`

`KINGLET_BASE_URL` doesn't match the origin in the browser. Set it to the exact
public URL — scheme and host — then restart the container.

### HTTPS shows a 526 or Traefik's default certificate

The domain probably has no certificate attached. In Dokploy, set the
certificate provider to **Let's Encrypt**; Coolify provisions one automatically
when the domain is verified. Redeploy after changing a Compose domain — Docker
Compose domains only pick up changes on redeploy. Behind Cloudflare, use
**Full (strict)** once the origin has a valid certificate; a 526 means Cloudflare
could not validate the origin certificate.

## From source

For development or a custom build, use the repository's
[Dockerfile and README](https://github.com/rushlightlab/kinglet). The published
image is built from the same source; development uses `pnpm install && pnpm dev`
with Node 26+.
