Storage sits behind a small driver interface, so the API, retention job, and
live tail never know what's underneath.

## sqlite (default)

better-sqlite3 with WAL mode and FTS5 trigram indexing. One file, zero
services, zero config:

```bash
KINGLET_DB_PATH=/data/kinglet.db
```

## libsql

The [libSQL](https://turso.tech) driver — for a local `file:` database or a
hosted [Turso](https://turso.tech) instance. Same container, same API:

```bash
# local libSQL file
KINGLET_STORAGE=libsql
KINGLET_DB_PATH=file:/data/kinglet.db

# Turso — just point at your database
KINGLET_DB_PATH=libsql://your-db.turso.io
KINGLET_DB_AUTH_TOKEN=eyJ…
```

With `KINGLET_STORAGE=auto` (the default), the driver is picked from the db
path scheme: plain paths use sqlite; `libsql://`, `https://`, `wss://`, and
`file:` URLs use libSQL.

<Aside type="note" title="FTS5 trigram caveat">
  Some hosted libSQL builds lack the trigram tokenizer. Kinglet detects this
  at boot and falls back to word-prefix search with a console warning rather
  than refusing to start.
</Aside>

### Notes for hosted Turso

```bash
docker run -d --name kinglet -p 8080:3000 \
  -e KINGLET_DB_PATH=libsql://your-db.turso.io \
  -e KINGLET_DB_AUTH_TOKEN=eyJ… \
  -e KINGLET_ADMIN_EMAIL=you@example.com \
  -e KINGLET_ADMIN_PASSWORD=change-me-please \
  ghcr.io/your-org/kinglet:latest
```

- **One Kinglet instance per database.** Ingest assumes a single writer; two
  instances against the same Turso DB would race on id read-back.
- **Every query is a network round trip.** Keep ingest batched (the SDK does
  this by default) and expect each enabled monitor's count check to cost one
  round trip per interval — a handful of monitors is fine.
- **Backups are Turso's job.** Litestream applies to local SQLite files only.
- Schema (events, monitors, alerts, FTS + triggers) is created automatically on
  first boot, same as a local file.
- Embedded replicas (local read cache with a remote primary) are a natural
  future upgrade — libSQL supports them; Kinglet's driver doesn't wire them up
  yet.

## ClickHouse (roadmap)

When a single node stops being enough, a ClickHouse driver implementing the
same interface is the graduation path — the API and UI won't change. And
since the [`Storage`
contract](https://github.com/your-org/kinglet/blob/main/apps/api/src/storage/types.ts)
is deliberately tiny, a custom Postgres or MySQL driver is a weekend project
if that's what your stack wants.
