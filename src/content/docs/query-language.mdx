The filter bar accepts a small, composable grammar:

| Syntax | Matches |
| --- | --- |
| `level:error` | events at exactly error level |
| `level>=warn` | level comparisons (`>`, `>=`, `<`, `<=`) |
| `service:api` | a specific service |
| `env:prod` | a specific environment |
| `key:0190f3a2-7c4e-7a11-9b65-2f1d8e6a4c30` | events ingested by that API key (UUID v7) |
| `"conn refused"` | message contains the phrase |
| `connection` | message contains the word — substring search, any position |
| `-healthcheck` | message must **not** contain this |

Combine freely:

```
level>=warn service:api -healthcheck
"connection refused" env:prod
```

The same grammar works everywhere: the UI filter bar, the `q` parameter on
`GET /v1/events`, and the SSE live tail (`GET /v1/stream?q=…`) — so your
filters follow you into the live view.

## In the UI

- **Time window** — pick a quick range from 5 minutes to 30 days, or open the
  picker and enter exact start and end times. Dragging the histogram creates a
  custom range you can clear from the same picker.
- **Live** — tails over SSE and is on by default; new events appear at the top
  as they arrive, with no polling involved. The optional refresh rate in the
  time picker is off by default and can re-query the window every 15 secs,
  1 min, or 5 mins; when enabled it rescales with the selected window.
- **Follow** — keeps you pinned to the newest event while live.
- **Services** — shows how many services reported events in this project; open
  it to toggle a `service:<name>` filter.
- **Histogram** — drag across any time range to zoom in; each bucket stacks
  by level.
- **Event drawer** — click any row for the full message, pretty-printed fields,
  the UUID v7 event id, and the API key that ingested it.

<Aside type="note" title="API key usage">
  `key:<id>` matches events ingested by that key. Open a key's actions in
  **Settings → projects & keys** and choose **View usage** to apply it from the
  UI. Attribution starts with events ingested after upgrading; older rows have
  no key id.
</Aside>

<Aside type="tip">
  Search is substring-based (FTS5 trigram), so `timeout` finds
  `connectiontimeouterror` — not just exact words.
</Aside>
